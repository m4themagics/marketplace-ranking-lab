# Задание 01 — split по времени решения

**Бюджет:** один вечер, 2–3 ч. **Фаза:** неделя 2.
**Код:** `temporal_split` в `src/mrl/data/temporal_split.py` — stub.

## Контракт уже зафиксирован

- Вход — по одной строке на customer-day decision example, не сырые покупки.
- История примера содержит только покупки строго раньше decision day.
- Границы: train `<= train_end`, validation `(train_end, valid_end]`, test `> valid_end`.
- Один customer может иметь решения в нескольких splits; изоляция пользователей здесь не
  нужна, point-in-time history — нужна.
- Функция сохраняет исходный index и не требует сортировки входа.

## Сначала тесты

1. Три ручных примера ровно на `train_end`, сразу после него и ровно на `valid_end`.
2. Несортированный frame возвращает labels в исходном порядке.
3. Один customer встречается в train, validation и test без удаления строк.
4. Missing decision timestamp приводит к явной ошибке, а не к молчаливому test label.
5. `train_end >= valid_end` приводит к ошибке.
6. Timezone-aware examples и cutoffs либо сравниваются в одной timezone, либо отклоняются
   понятной ошибкой; выбранное поведение фиксируется в тесте до реализации.

## Gate

Реализация начинается только после зафиксированного падения тестов. Готово, когда весь набор
зелёный и автор на бумаге строит history/target для одного customer-day на каждой границе.
