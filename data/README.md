# Data workspace

Данные в git не коммитятся — здесь живут только скрипты загрузки и fingerprints.

```text
data/
  raw/          # неизменяемый снимок исходника
  interim/      # промежуточные Parquet-таблицы
  processed/    # версионированная схема для экспериментов
```

## Датасет

**H&M Personalized Fashion Recommendations** — рабочий датасет экспериментов 01–04 и кандидат
для 05–06. Настоящие транзакции покупок примерно за два года, изображения и текстовые
атрибуты товаров, цена в каждой транзакции.

```bash
make fetch-hm   # articles.csv + transactions_train.csv, ~3,5 ГБ
```

Нужен токен в `~/.kaggle/access_token` и принятые правила соревнования на сайте — без них
API отдаёт список файлов, но возвращает 403 на скачивание.

Для 05–06 фиксируется только после зелёного
[kill-теста](../experiments/00_dataset_viability/README.md). Автоматического fallback нет:
Amazon Reviews 2023 имеет timestamp отзыва вместо покупки, а metadata — снимок на момент
краулинга, поэтому `price` и `average_rating` как признаки дают утечку из будущего.

Снимок загружен 2026-08-20. Источник, размеры, SHA-256 fingerprints, семантика времени и
известные отсутствующие поля зафиксированы в [`hm_snapshot.yaml`](hm_snapshot.yaml). Правила
соревнования принимаются владельцем Kaggle-аккаунта; raw-файлы остаются локальными и не
перераспространяются.

## Про честность разметки

У H&M нет query-логов, показов и propensities — есть только состоявшиеся покупки. Значит,
любая оценка здесь измеряет качество на наблюдённом распределении, а не то, что случилось бы
при выкатке. Всё, что моделируется синтетически (пропущенные показы, экспозиционное смещение,
обратная связь), маркируется явно и не выдаётся за индустриальное свидетельство.

Отдельно: ни один публичный датасет не публикует дату появления товара в каталоге. Первая
транзакция — прокси, и она смещает момент прибытия поздно для медленно продающихся товаров.
